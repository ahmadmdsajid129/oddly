# Oddly Deep Dive: What Is Really Built vs What the Founder Wants

**Date:** 2026-11-25 | **Branch:** `stage-B0-build` @ `54a4b27` | **Method:** read the code directly, ran small checks and the unit tests.
**Target behaviour:** the Oddly Walkthrough (24 Nov 2026) and the founder decisions D1–D8 in `docs/build-b0-conflicts.md`.

> [!IMPORTANT]
> The B0 report says every slice is "Verified". The code says otherwise. Much of the work exists as **library code and UI that is not connected to the real flow**. The single most important finding: **the live twin is chosen by a different, simpler formula than the one in the docs, the result screen shows invented numbers, and nothing ever locks a twin, so Keep → Orbit → chat unlock cannot happen for a real player.**

Status words used here: **Working** (wired end to end), **Partly working**, **Library only** (code exists, nothing in the app calls it), **Fake** (the screen shows made-up or hardcoded values), **Not built**.

## 1. One player's real journey today (Memes lane, 50 players)

| Step | What the founder wants | What the code actually does | Status |
|---|---|---|---|
| Open app | 18+ tick, then lane picker first | 18+ modal, then lane picker (`apps/web/src/app/page.tsx:215-233`). 18+ is stored only in the browser. | Partly working |
| Pick Memes, answer 5 | Memes Drop, 5 questions in mixed formats | Memes and Everyday are the only open lanes (`012_lanes_foundation.sql:110`). Each lane has its own Drop. Format cards exist. | Working |
| Twin is found | Weighted score: rare shared answers count more, each format has partial credit (`product.md §9`) | At submit, the API compares you only with people who **already** submitted (`routes/submissions.ts:405-445`). Scoring is `submissionSimilarity` (`scoring.ts:263`): a **plain average of overlap per question, with no rarity weighting**. | Wrong formula |
| | Slider: one step off = 0.83 | One step off = **0** (checked by running it) | Wrong |
| | Rank3: reversed order = 0.33 or 0 | Reversed order = **1.0**: every ranking counts as identical | Wrong |
| | Pick 2 of 6: overlap | 1 shared of 2 = 0.5 (Dice) | OK-ish |
| Ties and mutual pairs | Tie group within 0.01; history → country → hash; mutual pairs | No tie handling at submit. The mutual pairing code (`mutual-pairing.ts`) runs only in `PairingWorker`, which the scheduler calls with an **empty list** (`services/worker/src/index.ts:93`). | Library only |
| Twin improves during the day | Refresh about every 5 min | `provisional.worker.ts` is not called by anything, so the first players to submit keep a bad or empty twin all day. | Not wired |
| 07:00 lock + 07:05 recap | Final batch locks every twin | `executeMatchFinal` exists but **no cron schedules it** and close-drop doesn't start it (`scheduler.ts:60-80`). `finalizeMatches` is never called. **No recap job.** Twins stay "provisional" forever. | Not wired |
| Result screen | Real region, age band, real "N of 5", real player count, "Closest so far" below 200 players | The home page builds the result with **hardcoded values**: twin in "Berlin, Germany", age "25 to 34", `total_players_today: 3482`, rarest pick "Luminous Violet". If no twin exists, it still shows **4 of 5** (`page.tsx:308-325, 512-560`). If the API fails, it shows a full fake result. "Closest so far" can never appear because 3,482 is always above 200. | **Fake** |
| Tier on reveal | Oddness tier from rarity | The reveal screen derives "Mythic/Rare" from matched picks (`TwinRevealScreen.tsx:56`), not from oddness | Fake |
| Which twin is shown | Your one locked twin | `getMatchForPlayer` uses `findFirst` with no order (`matches.repo.ts:61`). If several people matched you, the twin shown is arbitrary, and it is labelled "Mutual" by default (`results.ts`: `is_mutual ?? true`). | Wrong |

**Answer to "how will I get a twin" today:** you get the best match among people who submitted **before** you, scored with an unweighted formula that ignores rarity and ranking order. The number shown to you is partly invented, and it never locks.

## 2. Matching math: docs vs code

| Item | Spec | Code | Verdict |
|---|---|---|---|
| Similarity used in production | `computeWeightedPolymorphicSimilarity` (`formats.ts:325`) | **Never called.** Production uses `submissionSimilarity` (Dice average) in submit, final batch, anti-twin and mutual pairing | Spec formula is dead code |
| Rarity weight I = log2(1/p) | Core idea of the product | Not used in matching at all. Used only for oddness. | Missing |
| Pairing order | Lexicographic: S, then history, then country, then hash | `mutual-pairing.ts:291` sorts edges by a weighted number (`S + 0.001H + …`) | Wrong (but unused) |
| Age bands | Display only (shown on twin card) | `pairing.worker.ts:90` splits pools into 18–24 / 25–34 / 35+. Nobody decided this. | Wrong (but unused) |
| Final batch candidate search | Best S in the lane | 5-of-5 bucket, else 4-of-5 bucket, else the first 200 rows by id (`pipeline.worker.ts:703-745`). A rarer 3-of-5 match is never considered when a 4-of-5 exists. | Approximation, not measured |
| Speed | — | Mutual pairing on 500 players takes **8.0 s** (test limit 3 s; `mutual-pairing.test.ts` fails) | Too slow |
| Oddness at submit | Percentile in today's lane pool | Percentile among earlier submitters in the same Drop. The first player of the day is compared with nobody. | Unstable early |
| Oddness in final batch | Same | `pct = raw × 100` (`pipeline.worker.ts:829`), which puts everyone in Common. Only affects rows created by the batch, which never runs. | Wrong (but unused) |

## 5. Jobs that actually run

Registered crons (`scheduler.ts`): `stage-drop` (06:30), `open-drop` (07:00), `close-drop` (06:59), `provisional-pairing` (every 5 min, but called with **no players**). Card rendering worker runs on demand.

**Not scheduled although the code exists:** final match batch, recap, provisional refresh, globe aggregation, lane history signature (BitMinHash), streak processing, creator-badge, meme curator, signals aggregation, wilson scoring, ML jobs, retention/purge.

## 8. Fix order (becomes Stage C0 in `task.md`)

1. **Honesty first:** remove every hardcoded or fallback value on player screens. Show real data or an honest empty state.
2. **Security:** block exclusion in all matching paths, lock `/v1/results` to the signed session, reject unsigned cookies, server-side 18+ record, anti-twin thresholds from config only.
3. **One similarity function:** production uses the spec's weighted, format-aware, symmetric formula. Delete or rename the Dice path.
4. **Real daily cycle:** schedule provisional refresh (with real candidates), final batch at 07:00 using mutual pairing and the lexicographic tie-break, recap at 07:05, and `finalizeMatches`. One pool per lane (no age bands).
5. **Result truth:** API returns `matched_picks` (real count), `total_players_today` (lane), region/age band from the twin's record, tie-group size and is_mutual from the stored match.
6. **Chat unlock backend:** trial start/answer/score, Door 2/3 evaluation on the server, both-confirm state stored, UI reads it.
7. **Wire B-tier:** bonus job + routes, Super twin, collector badges + opt-in share, per-lane streaks (lane column).
8. **Globe:** k ≥ 20 filter, scheduled aggregation, coarse regions, honest empty state (no invented arcs).
9. **Then:** measure matching at 1k/10k with the spec formula; fix pairing speed.
